Matters

Saved proposals come first; accepted Matters remain a separate collection. Reference and title identify every row.

Create Matter

A dedicated form separates Matter identity from the source. Analysis creates a saved proposal; it does not accept it.

Review a saved proposal

Approved direction A. Trusts use upright triangles with labels below; people remain rectangular. Selection reveals exact Evidence.

Accepted Matter

Confirmation opens the accepted graph and source. The success message appears after creation; the accepted heading remains on return visits.

Discard intake

Inline confirmation names the intake and consequences. Focus begins on Keep intake. Both terminal actions are disabled while a request is pending.

Recover an uncertain save

Preserve the form and local file while the page remains open. Resolve the reference before retrying analysis; never claim an uncertain save definitely failed.

Narrow-screen review

Stack graph, selected Evidence and source. View in source moves focus to the highlighted passage; a return link restores the relationship context. Decision controls follow the source in document order.

Other states and interaction rules

These requirements complete the workflow beyond the illustrated screens. Generated lettering and exact pixel colours are illustrative; the existing Matter Ledger tokens, accessible controls and domain contracts remain authoritative.

Empty collectionsKeep both collection headings. “No proposals awaiting confirmation.” / “No accepted Matters yet.” Create Matter remains available.
Loading collectionsUse a textual loading message inside each register; preserve headings. A failed collection does not hide the other.
AnalysingKeep entered values visible, disable repeat submission and announce “Uploading and analysing…”. No percentages, staged progress or saved-draft claim.
Invalid PDF or metadataShow field-associated errors with a focused summary. Preserve other inputs. Explain the actual admission failure and how to correct it.
No proposed relationshipsShow “Analysis completed with no proposed relationships.” Keep the source visible. Whole-proposal acceptance or discard remains available; do not show an error state.
Duplicate referenceOpen the existing proposal or Matter and explain that its reference already exists. No second model call in the normal duplicate path.
Temporary analysis failureOffer Retry analysis only when retryable. Check the external reference before invoking the model again.
Analysis unavailable or allowance exhaustedKeep existing Matter and proposal review available. Explain when analysis becomes available using the server-provided reset time. No invented usage counters.
Session expiredExplain that sign-in is required. Return to the requested saved resource after authentication where supported. Do not promise browser form or file recovery after navigation.
Proposal no longer availableExplain that the intake is no longer available; link to current Matters and proposals. Do not infer who accepted or discarded it.
Confirm or discard failureRetain the visible proposal, state the known outcome honestly and offer the appropriate recovery. No success navigation until the server confirms success.
Long content and small screensWrap Matter titles and source names. Keep labels readable and graph pan/zoom available. Use labelled keyboard-accessible relationship controls rather than relying only on edge clicks.

Keyboard focus is visible; primary targets are at least 44 pixels. Source highlights retain exact quote matching. Acceptance applies to the complete proposal. No real client material, per-relationship editing, multi-source intake, assignments or archiving is added.
