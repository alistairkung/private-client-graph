# Benchmark v2 · frozen study design

Design freeze, 21 November 2026. The unit of generalisation is an independently designed synthetic Matter family. A condition is one fixed bundle, presentation order and complete as-of answer key. A fresh extraction is one Observation within its condition. Record all three counts. This freeze fixes the design and evaluation protocols. The corpus freeze occurs after independent review and offline replay, before tuning.

The pre-execution amendment fixes ordinary metric eligibility and joint evidence scoring for both arms. Independent human approval of each linked case is still required. [Evidence policy, revision 1](evidence-policy-v1.md)

## Objectives and comparisons

Measure whether PCG reconstructs the complete current graph, including its supporting Evidence. Test whether the unchanged pipeline follows the operative document when recency diverges, preserves current relationships across presentation orders, and identifies the correct endpoint when a fact in another Source is necessary. Later, compare the frozen final pipeline with the unchanged baseline on four new families. Zero errors is a valid result. Hypotheses concern observable decisions and reviewable output.

## Family independence and corpus freeze

Reserve one held-out condition each for authority, temporal reconciliation, genuine cross-Source reasoning and a realistic composite. Give the isolated authors the [capability briefs](held-out-briefs.md). Keep Sources, truth, Evidence approvals and ideals under independent custody outside the development catalog and tuning context. Related stages, reordered or padded variants and retellings share a family. Shared relationship types or graph shape can arise independently. The independent reviewer compares chronology, narrative structure, placement of decisive evidence and reasoning with development and other final families. Record authorship, reviewer, exposure, lineage, disposition and the rationale for independence. Reclassify or replace an overlapping family before freeze.

Use the repository authoring sequence: answer key → Sources → bidirectional semantic audit → exact Source-specific approvals → ideal extraction → deterministic replay. Audit every supported relationship in both directions, dated governing facts, absences and unaffected edges. Have a human review completeness and realism. Hash the exact ordered Sources, truth, approvals, diagnostic annotations, ideals and protocol revision. Give development owners only the final fixture identifiers, digest commitments and review status. A discovered fixture defect requires a versioned decision, renewed review and disclosure of affected comparisons. Keep the original and historical observations. [Authoring workflow](../docs/workflows/synthetic-case-authoring.md)

For a hard cross-Source target, an independent reviewer must recover the unique edge with the full bundle and identify at least two plausible endpoints after masking the linking fact everywhere. Document both judgments before freeze. Annotate the **minimum sufficient sets** of exact (Source ID, quotation) pairs that establish all necessary facts. A set can contain one span when that span establishes everything. Such a span disqualifies the hard condition. Keep link-only annotations separate from ordinary individually approved quotations. Verify compatibility with the existing per-edge quote contract during authoring. If an ideal can achieve perfect graph agreement but the protected quotation rule cannot express its support, record the discrepancy and seek a separate decision before admission. Manufacturing an individually sufficient quotation would invalidate the comparison.

**Final paired evaluation.** Freeze both evaluation protocols and all four held-out packages before tuning. After development, record the selected final architecture, prompts, settings, dependencies and digests before releasing any held-out input to either arm. Run one fresh Observation per arm on identical ordered Sources per Matter. Interleave the arms within family, baseline first on families 1 and 3, final first on 2 and 4. Use identical evaluator versions. No performance-driven retries, fixture edits or configuration selection after unsealing. Document provider/model differences and any missing pair.

**Budget.** Authoring and review use zero extraction calls. Development cap proposed: 18 attempted calls, subject to explicit execution approval after fixture admission. Reserve eight attempted calls for the four paired final comparisons. The reserve covers four single-call baseline and four single-call final executions. If the eventual architecture uses more than one paid stage, cost the full matrix and obtain a revised cap before unsealing. Failed calls consume the cap, and unexecuted slots remain visible. Optimisation experiments require a separate budget. No live execution is authorised by this specification.

## Scoring and acceptance

| Report | Unit and denominator |
| --- | --- |
| Complete graph | Per scored Observation report TP/FP/FN, exact graph and micro-F1 using the existing semantic-edge contract. Each scored Observation contributes once to pooled counts, including temporal repeats. Also group by condition so repeated T3 cannot obscure the other cases. |
| Target decisions | Predeclare required, forbidden and unaffected edge lists for each relevant condition. Report required recovered/required, forbidden generated/forbidden, unaffected retained/unaffected, critical omissions and all other FP/FN. Report raw counts and N/A for an empty diagnostic set. Diagnostic groups may overlap. |
| Evidence | Preserve approved-quote passes/TP and approved Source/quote associations/all assessed associations on TPs. Keep the scorer's existing empty-denominator handling. On annotated correct targets, report those whose **own attached Evidence** contains a complete approved sufficient set / annotated correct targets. Also list missed targets and the number planned so a missing edge cannot disappear from the report. Zero eligible targets gives N/A. |
| Coverage and cost | Scored/planned, plus failed, uncertain, pending and unavailable. Failed slots have no graph score. Report tokens, latency, attempted calls and priced cost by Observation and arm; distinguish unpriced usage from zero. |
| Final comparison | One row per family with both complete scores, FP/FN fixes and regressions by edge, evidence changes, cost and latency deltas (final minus baseline). Use paired deltas only where both observations scored; show partial coverage. Report pooled scores with denominators. Four families support case-specific transfer claims. |

Admission checks cover unique IDs and valid references, exact quote occurrence in the named Source, equal truth and designated invariants across each pair, ideal graph replay, Source associations and complete planned coverage. Validate the new diagnostic with complete, partial, wrong-Source and wrong-edge attachments, acceptable alternatives, missing target, and empty denominator. Perturb an ideal with a forbidden edge and a critical omission. Saved execution, reopening and re-scoring must consume zero paid attempts. Independent semantic review remains a separate gate.
